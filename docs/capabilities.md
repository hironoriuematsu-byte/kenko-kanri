# 健康管理Web 導入検討ポイントへの対応状況

作成: 2026-09-14 / うえまつ産業医事務所(Mestate LLC)

企業が健康管理システムの導入を検討する際に重視される項目について、
本システムの対応状況をまとめる。営業資料・問い合わせ回答の根拠として使う。

| # | 検討ポイント | 状況 | 備考 |
|---|---|---|---|
| 1 | 特殊健診・雇入時健診への対応 | ✅ 対応 | 健診種別(定期・雇入時・特殊)を持ち、特殊健診は種類(有機溶剤・鉛 など)も記録できる |
| 2 | 複数担当者・拠点/職種ごとの権限 | △ 一部対応 | 拠点(事業場)単位の分離と「閲覧のみ」の担当者に対応。職種・機能単位の細かな権限は今後 |
| 3 | 受診勧奨対象者のフォローアップ | ✅ 対応 | 総合判定D以上を自動で「受診勧奨」とし、勧奨済・受診済まで追跡。一覧・報告書に反映 |
| 4 | 法改正への対応 | ✅ 対応(運用) | 判定基準は画面から変更可。法定項目の追加は小規模なコード変更で対応(クレアチニン追加の実績) |
| 5 | 個人の全事象の時系列フォロー | ✅ 対応 | 健診・ストレスチェック・面談・就業判定・受診勧奨を1つの時系列で表示。閲覧は監査ログに記録 |
| 6 | 勤怠管理等の他データとの連携 | △ 一部対応 | CSVによる取込・出力に対応。API連携は未対応(要望に応じて設計) |

## 1. 特殊健診・雇入時健診

- 健診種別: `定期健診` / `雇入時健診` / `特殊健診`
- 特殊健診は **種類**(有機溶剤・鉛・電離放射線・じん肺 など)を取込時・個別入力時に指定でき、
  一覧と個人の時系列に表示される
- 定期健康診断結果報告書(様式第6号)の集計は定期健診のみを対象とし、他の種別は混ざらない
- **年に複数回の定期健診**(特定業務従事者の6か月ごとの健診など)は「実施回」で分けて
  取り込み、一覧・集計・報告書を回ごとに出せる。同じ方の記録への統合は同じ回の中でだけ行う
- 検査項目は健診機関のCSVの見出しをそのまま保持するため、特殊健診固有の項目
  (尿中代謝物、血中鉛 など)も登録できる。法定項目の自動判定は定期健診の項目が対象

## 2. 権限

### 拠点(事業場)ごとの分離

企業(事業場)単位でデータが分かれており、担当者は自社(自事業場)の情報だけを閲覧・操作できる。
複数の事業場を持つ企業は、**事業場ごとに企業を登録**して担当者を紐付けることで、
拠点ごとの閲覧範囲を分けられる(労働基準監督署への報告も事業場単位のため、この単位が実務と合う)。

### 役割と操作範囲

| 役割 | 閲覧 | 登録・編集 | 就業判定 |
|---|---|---|---|
| 実施者(産業医事務所) | 全企業 | 可 | 可 |
| 事業者担当者 | 自社 | 可 | 不可(閲覧のみ) |
| 事業者担当者(**閲覧のみ**) | 自社 | **不可** | 不可 |
| 従業員 | 本人分 | 不可 | 不可 |

- 「閲覧のみ」はストレスチェックWebの **ユーザー管理 → メンバー一覧** で実施者が設定する
- 閲覧のみの担当者は、画面上の登録・取込のボタンが表示されず、直接URLを開いても戻される。
  健診の取込・受診勧奨の更新はサーバー側でも拒否する(`hm_company_can_write`)
- 誰がいつ何を見たか・変更したかは、すべて監査ログ(`hm_access_logs`)に残る

### 今後(未対応)

- 職種(人事・衛生管理者・保健師 など)ごとに機能単位で権限を分ける
- 議事録・巡視記録など健診以外の登録について、サーバー側でも「閲覧のみ」を強制する
  (現状は画面上の制御)

## 3. 受診勧奨のフォローアップ

- 取込時に総合判定がD(またはE)の方は自動で **受診勧奨** の状態になる
- 一覧の「受診勧奨」欄で `受診勧奨 → 勧奨済 → 受診済` と更新できる(実施者・事業者担当者)
- 集計に「受診勧奨 未対応 n名 / 勧奨済 n名 / 受診済 n名」を表示
- 就業判定結果報告書・健康診断結果一覧のCSVに「受診勧奨」の列を出力。
  就業判定結果報告書では受診勧奨が必要な方(受診勧奨・勧奨済・受診済)は「要」、措置不要は空欄。
  その右に「産業医面談」の列があり、要就業制限の方は「要」
- 一覧の「表示」ボタンで、要医療項目(D)あり・就業制限項目(R)あり・DまたはRありの方だけに
  絞り込める(全選択は表示中の方だけが対象。一括判定ボタンは絞り込みに関係なく全員が対象)
- 就業判定の一括入力では、要医療項目(D)・就業制限項目(R)のある方の「医師の意見」の先頭に、
  異常の区分と受診先に言い換えた受診勧奨の文章が自動で入る(`lib/referral.ts`)。
  例: 「肝機能異常あり内科（消化器内科）受診」「高血圧・脂質異常あり内科受診、心電図異常あり内科（循環器内科）受診」
  | 項目 | 区分 | 受診先 |
  |---|---|---|
  | 胸部エックス線 | 胸部エックス線異常 | 内科（呼吸器内科） |
  | 収縮期・拡張期血圧 | 高血圧 | 内科 |
  | AST・ALT・γ-GT | 肝機能異常 | 内科（消化器内科） |
  | 中性脂肪・HDL・LDL | 脂質異常 | 内科 |
  | 血糖・随時血糖・HbA1c・尿糖 | 耐糖能異常 | 内科 |
  | 血色素・赤血球数 | 貧血 | 男性: 内科 / 女性: 内科（婦人科） |
  | 心電図 | 心電図異常 | 内科（循環器内科） |
  | 尿蛋白・クレアチニン | 腎機能異常 | 内科（腎臓内科） |
  | 視力 | 視力低下 | 眼科 |
  | 聴力 | 聴力低下 | 耳鼻咽喉科 |
  | 上記以外 | 「<項目名>異常」 | 医療機関 |
  (定型文・自由記入は選択者に共通で後ろに付く。0132 `hm_bulk_work_judgment(p_notes, p_condition_ids)`)
- **判定条件「受診が条件」**: 要医療項目(D)・就業制限項目(R)があるのに「通常勤務可」とする場合の
  条件付き判定。医師の意見とは別の欄(`hm_checkups.work_judgment_condition`)に持ち、
  一括判定(通常勤務可のときD・Rのある方に自動で付く。チェックで外せる)、一覧の1人ずつのチェック、
  健診個人票の就業判定で付け外しできる。通常勤務可以外に変えると自動で消える。
  就業判定結果報告書では「就業判定」の右の「判定条件」列に「受診が条件」と出る。
  (以前の定型文「但し受診が条件」は 0132 で判定条件に移し、医師の意見から取り除いた)
- 更新は監査ログに記録される

## 4. 法改正への対応

- **判定基準(A〜D・就業制限R)**: 産業医事務所ダッシュボードの「判定基準の設定」から変更でき、
  「判定を再計算」で取り込み済みのデータにも反映できる
- **法定項目の追加・変更**: 項目の定義(`lib/judgment.ts` の `LEGAL_ITEMS`)と判定基準の
  登録SQLを追加する。2026年のクレアチニン追加を同じ手順で対応した
- **報告書の様式変更**: 集計の区分(`lib/checkupReport.ts`)とCSVの列を変更する
- いずれもデータ構造を変えずに対応でき、過去データは影響を受けない

### 自動判定の補足(数値以外の項目)

- **視力・聴力**: 右・左の列をそれぞれ判定し、悪い側が総合判定に反映される。
  聴力は 1000Hz・4000Hz それぞれ。「0.7(1.2)」のような裸眼(矯正)は矯正視力で判定。
  聴力が「所見なし/所見あり」の文字記載なら A/C とする
- **血圧2回測定**: 「平均」の列が無く収縮期(または拡張期)の列が2つ以上あるときは、
  取込時に平均を計算して `収縮期血圧(平均)`/`拡張期血圧(平均)` として保存し、平均で判定する。
  各回の値はそのまま保存し、判定は付けない
- **心電図**: 日本人間ドック学会「心電図健診判定マニュアル」(平成26年4月)表2に沿って、
  所見の語句を A〜D に対応づける(D1・D2 は D、ペースメーカー調律は E)。
  左室高電位に ST-T 変化を伴えば D。表に無い所見は C(要確認)。
  事務所の方針として「軽度(の)ST-T異常」「軽度(の)ST-T変化」は B
- **胸部エックス線**: 「異常なし」は A、所見があれば B。所見に
  腫瘍・腫瘤・結節・空洞・粒状・網状・すりガラス・胸水・狭窄・動脈瘤・蜂巣・気腫・うっ血(鬱血)・
  リンパ節腫大・縦隔(縦郭)拡大・浸潤・コンソリデーション・胸膜プラーク・破壊・溶骨・骨折・
  心拡大・癌(がん)・転移・結核・無気肺・肺炎・胸膜炎 の語句を含めば D
  (部分一致のため「右胸水」「肺がん疑い」「腹部大動脈瘤」も D。胸膜肥厚は B)。
  「陳旧性」の所見は治癒後の変化として B(陳旧性肺結核 → B)。「、」「・」スペースなどで区切られた
  所見はそれぞれ判定し、最も重いものを採用(陳旧性肺結核、右胸水 → D、陳旧性肺結核 右胸水 → D)。
  語句の一覧は `lib/textJudgment.ts` の `CHEST_XRAY_D_WORDS`

## 5. 個人の時系列フォロー

- 個人統合ビュー(実施者)と個人カルテ(実施者・事業者担当者)で、
  **健診(種別・総合判定・就業判定・受診勧奨)、ストレスチェック(高ストレス・面接指導申出)、面談**
  を日付順に表示する
- 健診個人票では直近6年分の検査値を横並びで比較できる
- 個人の閲覧はすべて監査ログに記録される(だれが・いつ・だれの記録を見たか)

## 6. 他データとの連携

現在できること:

- 健診機関のCSVの取込(列の割り当てを画面で調整)
- **複数の健診機関のCSVを1人の記録に統合**(同年度・同種別に同じ方の記録があれば
  検査項目を追加。総合判定は重いほうを採用。取込単位で取り消し可)
- 健診結果PDFからの取込は未対応(下記)
- 健康診断結果一覧・就業判定結果報告書・定期健康診断結果報告書サマリのCSV出力
- ストレスチェックWebとの連携(同一アカウント・同一の企業台帳・高ストレス者の参照)

未対応(要望に応じて設計する):

- 勤怠システム・人事システムとのAPI連携
- 従業員マスタの自動同期(現状は招待・CSVによる登録)

勤怠情報(時間外労働時間)は、長時間労働者の面談対象者の抽出に使えるため、
CSV取込による対応から始め、需要に応じてAPI連携へ進める想定。

### 健診結果PDFからの取込(検討中)

健診機関から結果がPDFでしか提供されない場合の選択肢。

| 方式 | 精度 | 個人情報の扱い | 費用 |
|---|---|---|---|
| A. ブラウザ内でPDFの文字を読み取り、個別入力の下書きにする | 文字データのPDFなら中程度。スキャン画像は不可 | 端末内で完結(外部送信なし) | なし |
| B. AI(文書読み取り)で表形式に変換 | 高い。スキャン画像も可 | **医療情報を外部サービスへ送る**ため、委託契約・本人への周知が必要 | 従量 |

いずれも**読み取り結果を人が確認してから登録**する画面を挟む(自動判定はその後に走る)。
まずAで様子を見て、スキャンPDFが多ければBを検討する。

# 健康管理Web 導入検討ポイントへの対応状況

作成: 2026-09-14 / うえまつ産業医事務所(Mestate LLC)

企業が健康管理システムの導入を検討する際に重視される項目について、
本システムの対応状況をまとめる。営業資料・問い合わせ回答の根拠として使う。

| # | 検討ポイント | 状況 | 備考 |
|---|---|---|---|
| 1 | 特殊健診・雇入時健診への対応 | ✅ 対応 | 健診種別(定期・雇入時・特殊)を持ち、特殊健診は種類(有機溶剤・鉛 など)も記録できる |
| 2 | 複数担当者・拠点/職種ごとの権限 | △ 一部対応 | 拠点(事業場)単位の分離と「閲覧のみ」の担当者に対応。職種・機能単位の細かな権限は今後 |
| 3 | 受診勧奨対象者のフォローアップ | ✅ 対応 | 総合判定D以上を自動で「受診勧奨」とし、勧奨済・受診済まで追跡。一覧・報告書に反映 |
| 4 | 法改正への対応 | ✅ 対応(運用) | 判定基準は画面から変更可。法定項目の追加は小規模なコード変更で対応(クレアチニン追加の実績) |
| 5 | 個人の全事象の時系列フォロー | ✅ 対応 | 健診・ストレスチェック・面談・就業判定・受診勧奨を1つの時系列で表示。閲覧は監査ログに記録 |
| 6 | 勤怠管理等の他データとの連携 | △ 一部対応 | CSVによる取込・出力に対応。API連携は未対応(要望に応じて設計) |

## 1. 特殊健診・雇入時健診

- 健診種別: `定期健診` / `雇入時健診` / `特殊健診`
- 特殊健診は **種類**(有機溶剤・鉛・電離放射線・じん肺 など)を取込時・個別入力時に指定でき、
  一覧と個人の時系列に表示される
- 定期健康診断結果報告書(様式第6号)の集計は定期健診のみを対象とし、他の種別は混ざらない
- 有所見者数の基準は C 以上(C・D・E・R)で統一。B(軽度異常)は有所見に数えない
  (健康診断管理の集計・健診項目別の集計・一覧の有所見項目・取込時の has_findings がすべて同じ基準)
- **年に複数回の定期健診**(特定業務従事者の6か月ごとの健診など)は「実施回」で分けて
  取り込み、一覧・集計・報告書を回ごとに出せる。同じ方の記録への統合は同じ回の中でだけ行う
- 検査項目は健診機関のCSVの見出しをそのまま保持するため、特殊健診固有の項目
  (尿中代謝物、血中鉛 など)も登録できる。法定項目の自動判定は定期健診の項目が対象
- **氏名の扱い(0133)**: 取込では漢字の氏名列を「氏名」に、カナの列(氏名カナ・フリガナ)を
  「フリガナ」に自動で割り当てる(漢字の列が無ければカナを氏名にする)。「所属(部署)」も取り込む。
  一覧では氏名の上にフリガナ、下に生年月日を小さく表示し(所属・社員番号は列幅の都合で出さず、有所見項目の列幅に回す)、就業判定結果・
  健康診断結果一覧CSVには氏名の隣に「フリガナ」「生年月日」「性別」「所属」を出力する。
  同姓同名は取込時に 社員番号 → 氏名+生年月日 → 氏名 の順で本人を特定する

## 2. 権限

### 拠点(事業場)ごとの分離

企業(事業場)単位でデータが分かれており、担当者は自社(自事業場)の情報だけを閲覧・操作できる。
複数の事業場を持つ企業は、**事業場ごとに企業を登録**して担当者を紐付けることで、
拠点ごとの閲覧範囲を分けられる(労働基準監督署への報告も事業場単位のため、この単位が実務と合う)。

### 役割と操作範囲

| 役割 | 閲覧 | 登録・編集 | 就業判定 |
|---|---|---|---|
| 実施者(産業医事務所) | 全企業 | 可 | 可 |
| 事業者担当者 | 自社 | 可 | 不可(閲覧のみ) |
| 事業者担当者(**閲覧のみ**) | 自社 | **不可** | 不可 |
| 従業員 | 本人分 | 不可 | 不可 |

- 事業者担当者向けの **使い方マニュアル**を画面内に持つ(`/company/manual`、`lib/manual.ts`)。
  はじめに／健康診断管理／産業医面談管理／衛生委員会議事録／衛生管理者巡視記録／産業医巡視記録／
  作業環境測定／従業員カルテ／よくある質問 のセクションをタブで切り替える。
  各画面の見出し横の「？ 使い方」から該当セクションを直接開ける。実施者も閲覧できる
- 「閲覧のみ」はストレスチェックWebの **ユーザー管理 → メンバー一覧** で実施者が設定する
- 閲覧のみの担当者は、画面上の登録・取込のボタンが表示されず、直接URLを開いても戻される。
  健診の取込・受診勧奨の更新はサーバー側でも拒否する(`hm_company_can_write`)
- 誰がいつ何を見たか・変更したかは、すべて監査ログ(`hm_access_logs`)に残る

### 今後(未対応)

- 職種(人事・衛生管理者・保健師 など)ごとに機能単位で権限を分ける
- 議事録・巡視記録など健診以外の登録について、サーバー側でも「閲覧のみ」を強制する
  (現状は画面上の制御)

## 3. 受診勧奨のフォローアップ

- 取込時に総合判定がD(またはE)の方は自動で **受診勧奨** の状態になる。「判定を再計算（事務所基準）」で総合判定が変わったときも同じ規則で合わせる(0143。勧奨済・受診済は変えない)
- 一覧の「受診勧奨」欄で `受診勧奨 → 勧奨済 → 受診済` と更新できる(実施者・事業者担当者)
- 集計に「受診勧奨 未対応 n名 / 勧奨済 n名 / 受診済 n名」を表示
- 就業判定結果報告書・健康診断結果一覧のCSVに「受診勧奨」の列を出力。
  就業判定結果CSVでは受診勧奨が必要な方(受診勧奨・勧奨済・受診済)は「要」、措置不要は「不要」。
  その右に「産業医面談」の列があり、要就業制限の方と医師の意見に「産業医面談」が含まれる方は「要」、それ以外は「不要」
- 一覧の「表示」ボタンで、要医療項目(D)あり・就業制限項目(R)あり・DまたはRあり・
  要受診勧奨(受診勧奨が未対応)・要就業制限(要就業制限・要休業)・要産業医面談(要就業制限、または医師の意見に「産業医面談」)の方だけに
  絞り込める(全選択は表示中の方だけが対象。一括判定ボタンは絞り込みに関係なく全員が対象)
- 「受診勧奨通知書（1人1ページ）」ボタンで、受診勧奨となった方へ本人に渡す通知文書をまとめて作れる
  (`/office/[companyId]/checkups/notices`・`/company/checkups/notices`)。
  受診勧奨が未対応・勧奨済の方、判定条件が「受診が条件」の方、医師の意見に「受診」を含む方があらかじめ絞り込まれて全員チェック付きで並び(外すだけ)、
  表題・本文・結び・発行日・担当連絡先を画面で直してから「印刷 / PDFとして保存」で全員分を1つのPDFにする。
  各ページには健診日・総合判定・受診をお勧めする項目(要医療D・就業制限Rの項目のみ。Cは載せない)・就業判定・医師の意見(例: 肝機能異常あり内科（消化器内科）受診)が入る。
  出力後に「通知した方を勧奨済にする」で受診勧奨の状態をまとめて更新できる(閲覧のみの担当者は不可)。
  医師の意見が空の方(判定の再計算であとからDになった方など)は空欄の通知書を渡さないよう最初はチェックを外し、
  実施者の画面では「受診勧奨の文章を自動で入れる」で `lib/referral.ts` の文章を `hm_save_work_judgment_note` で入れられる。
  文書の下にはキリトリ線付きの「受診報告」欄(氏名・受診日・医療機関・診療科・受診結果のチェック・診断名と医師の指示・提出日と署名)が付き、
  本人が受診後に記入して担当部署へ提出する雛形になる(チェックで外せる。提出期限を全員共通で入れられる)
- 受診勧奨通知書には本人専用のQRコードも印字できる(0142)。読み取ると `/report/<受付番号>`(ログイン不要)が開き、
  本人確認(生年月日。無ければ社員番号、無ければ氏名)のうえ受診日・医療機関・診療科・受診結果・医師の指示を送信できる。
  送信されると `hm_consult_reports` に保存され、その健診結果の受診勧奨が自動で「受診済」になる。
  受付番号は推測できない乱数で `hm_report_tokens` に持ち(画面からは読めずRPC経由のみ)、発行から1年で無効。
  一覧の「受診勧奨」欄に「📱 報告あり: 異常なし」のように出て、個人票の「本人からの受診報告」で全文を見られる(実施者と当該企業の担当者)
- 「産業医面談通知書（1人1ページ）」ボタン(`/office/[companyId]/checkups/interview-notices`・`/company/checkups/interview-notices`)で、
  就業判定が要就業制限・要休業の方と医師の意見に「産業医面談」を含む方(絞り込み済み・全員チェック付き)へ
  面談を案内する文書を同じ形式で作れる。面談日・時間・方法・場所(全員共通)を入れると文書に印字され、
  「選択した方の面談予定を産業医面談管理に登録」ボタンでそのまま面談予定(健診事後措置面談・予定)をまとめて登録できる
  (0141 `hm_bulk_create_interviews`。実施者と書き込みできる事業者担当者。カルテ未紐付けの方は社員番号→氏名+生年月日→氏名で
  探して紐付け、なければ作成。`hm_interviews.checkup_id` で元の健診結果を持ち、同じ健診結果からは二重に登録しない)
- 就業判定の一括入力では、要医療項目(D)・就業制限項目(R)のある方の「医師の意見」の先頭に、
  異常の区分と受診先に言い換えた受診勧奨の文章が自動で入る(`lib/referral.ts`)。
  例: 「肝機能異常あり内科（消化器内科）受診」「高血圧・脂質異常あり内科受診、心電図異常あり内科（循環器内科）受診」
  | 項目 | 区分 | 受診先 |
  |---|---|---|
  | 胸部エックス線 | 胸部エックス線異常 | 内科（呼吸器内科） |
  | 収縮期・拡張期血圧 | 高血圧 | 内科 |
  | AST・ALT・γ-GT | 肝機能異常 | 内科（消化器内科） |
  | 中性脂肪・HDL・LDL | 脂質異常 | 内科 |
  | 血糖・随時血糖・HbA1c・尿糖 | 耐糖能異常 | 内科 |
  | 血色素・赤血球数 | 貧血（要医療の高値基準 Hb 男18.1/女16.1 以上、赤血球数 男600/女550 以上なら「多血」） | 貧血: 男性 内科 / 女性 内科（婦人科）、多血: 内科 |
  | 心電図 | 心電図異常 | 内科（循環器内科） |
  | 尿蛋白・クレアチニン | 腎機能異常 | 内科（腎臓内科） |
  | 視力 | 視力低下 | 眼科 |
  | 聴力 | 聴力低下 | 耳鼻咽喉科 |
  | 上記以外 | 「<項目名>異常」 | 医療機関 |
  (定型文・自由記入は選択者に共通で後ろに付く。0132 `hm_bulk_work_judgment(p_notes, p_condition_ids)`)
- **判定条件「受診が条件」**: 要医療項目(D)・就業制限項目(R)があるのに「通常勤務可」とする場合の
  条件付き判定。医師の意見とは別の欄(`hm_checkups.work_judgment_condition`)に持ち、
  一括判定(通常勤務可のときD・Rのある方に自動で付く。チェックで外せる)、一覧の1人ずつのチェック、
  健診個人票の就業判定で付け外しできる。通常勤務可以外に変えると自動で消える。
  就業判定結果報告書では「就業判定」の右の「判定条件」列に「受診が条件」と出る。
  (以前の定型文「但し受診が条件」は 0132 で判定条件に移し、医師の意見から取り除いた)
- 更新は監査ログに記録される

## 4. 法改正への対応

- **判定基準(A〜D・就業制限R)**: 産業医事務所ダッシュボードの「判定基準の設定」から変更でき、
  「判定を再計算」で取り込み済みのデータにも反映できる
- **法定項目の追加・変更**: 項目の定義(`lib/judgment.ts` の `LEGAL_ITEMS`)と判定基準の
  登録SQLを追加する。2026年のクレアチニン追加を同じ手順で対応した
- **報告書の様式変更**: 集計の区分(`lib/checkupReport.ts`)とCSVの列を変更する
- いずれもデータ構造を変えずに対応でき、過去データは影響を受けない

### 自動判定の補足(数値以外の項目)

- **視力・聴力**: 右・左の列をそれぞれ判定し、悪い側が総合判定に反映される。
  聴力は 1000Hz・4000Hz それぞれ。「0.7(1.2)」のような裸眼(矯正)は矯正視力で判定。
  聴力が「所見なし/所見あり」の文字記載なら A/C、「1/2」の区分番号(1=所見なし、2=所見あり)なら A/C とする
  (dB の実測値は 5dB 刻みなので 1・2 と区別できる)
- **血圧2回測定**: 「平均」の列が無く収縮期(または拡張期)の列が2つ以上あるときは、
  取込時に平均を計算して `収縮期血圧(平均)`/`拡張期血圧(平均)` として保存し、平均で判定する。
  各回の値はそのまま保存し、判定は付けない
- **心電図**: 日本人間ドック学会「心電図健診判定マニュアル」(平成26年4月)表2に沿って、
  所見の語句を A〜D に対応づける(D1・D2 は D、ペースメーカー調律は E)。
  左室高電位に ST-T 変化を伴えば D。表に無い所見は C(要確認)。
  事務所の方針として「軽度(の)ST-T異常」「軽度(の)ST-T変化」は B
- **胸部エックス線**: 「異常なし」は A、所見があれば B(様式第6号の有所見者数には C 以上だけを数えるため、B は含めない)。所見に
  腫瘍・腫瘤・結節・空洞・粒状・網状・すりガラス・胸水・狭窄・動脈瘤・蜂巣・気腫・うっ血(鬱血)・
  リンパ節腫大・縦隔(縦郭)拡大・浸潤・コンソリデーション・胸膜プラーク・破壊・溶骨・骨折・
  心拡大・癌(がん)・転移・結核・無気肺・肺炎・胸膜炎 の語句を含めば D
  (部分一致のため「右胸水」「肺がん疑い」「腹部大動脈瘤」も D。胸膜肥厚は B)。
  「陳旧性」の所見は治癒後の変化として B(陳旧性肺結核 → B)。「、」「・」スペースなどで区切られた
  所見はそれぞれ判定し、最も重いものを採用(陳旧性肺結核、右胸水 → D、陳旧性肺結核 右胸水 → D)。
  語句の一覧は `lib/textJudgment.ts` の `CHEST_XRAY_D_WORDS`

## 5. 個人の時系列フォロー

- 個人統合ビュー(実施者)と個人カルテ(実施者・事業者担当者)で、
  **健診(種別・総合判定・就業判定・受診勧奨)、ストレスチェック(高ストレス・面接指導申出)、面談**
  を日付順に表示する
- 健診個人票では直近6年分の検査値を横並びで比較できる
- 個人の閲覧はすべて監査ログに記録される(だれが・いつ・だれの記録を見たか)

## 6. 他データとの連携

現在できること:

- 健診機関のCSVの取込(列の割り当てを画面で調整。法定項目(自動判定)と判別できる列以外は、「判定」を含む見出しや「判」で始まる見出しの列(法定項目の語が続いても)を含めて「取り込まない」が既定)。
  **事業者担当者はCSVまたはPDFをそのまま「送る」だけ**(複数ファイルをまとめて送れる。年度・種別・連絡事項を添えられる)。
  産業医事務所ダッシュボードに「取込待ちのファイル」として表示され、
  CSVは実施者が「取り込む」で取込画面を開き、列の割り当てを指定して取り込む(0135 `hm_csv_uploads`)。
  PDFは非公開バケット hm-files の `<company_id>/checkup-uploads/` に保存され(0136)、実施者が
  「ダウンロード」してCSVに変換し、その企業の取込画面から取り込む。
  送られたCSV・PDFの原本は取込後も保管され、実施者の健診一覧「送られたファイルの原本」から
  ダウンロード・削除できる。CSVはダッシュボードからもダウンロードでき、取込完了画面の
  「送られたCSVの原本を削除する」で取込直後に削除できる。「破棄」(取り込まない)のときは即時に消える。
  事業者担当者の一覧には「取込待ち」の件数が出る。
  取込待ちのファイルはチェックで複数選び(企業名を押すとその企業の分をまとめて選択)、
  「一括ダウンロード(ZIP。企業ごとのフォルダに分けて格納)」「選択を処理済みにする」「選択を破棄する」で一括処理できる(jszip)。
  取込が完了すると産業医事務所ダッシュボードに「健診結果の取込があります」と表示され、
  実施者が「確認」を押すまで残る(0134 `hm_import_notices`)
- **複数の健診機関のCSVを1人の記録に統合**(同年度・同種別に同じ方の記録があれば
  検査項目を追加。総合判定は重いほうを採用。取込単位で取り消し可)
- 健診結果PDFからの取込は未対応(下記)
- 健康診断結果・就業判定結果のCSV出力(健康診断管理の画面から。定期健康診断結果報告書(様式第6号)は
  同じ画面の「転記用集計」を開いて厚生労働省の入力支援サービスに転記する。以前の別ページとCSV出力は廃止)
- ストレスチェックWebとの連携(同一アカウント・同一の企業台帳・高ストレス者の参照)

### 健診結果PDFからの取込(検討中)

健診機関から結果がPDFでしか提供されない場合の選択肢。

| 方式 | 精度 | 個人情報の扱い | 費用 |
|---|---|---|---|
| A. ブラウザ内でPDFの文字を読み取り、個別入力の下書きにする | 文字データのPDFなら中程度。スキャン画像は不可 | 端末内で完結(外部送信なし) | なし |
| B. AI(文書読み取り)で表形式に変換 | 高い。スキャン画像も可 | **医療情報を外部サービスへ送る**ため、委託契約・本人への周知が必要 | 従量 |

いずれも**読み取り結果を人が確認してから登録**する画面を挟む(自動判定はその後に走る)。
まずAで様子を見て、スキャンPDFが多ければBを検討する。
- 産業医面談は、意見書を「企業側に公開し、面談を実施済にする」で保存すると実施済になる
  (0137 `hm_mark_interview_done`。実施記録の「実施済にする」チェックは廃止。実施記録は所見・指導内容・非公開メモを
  「所見と指導内容」の1欄に統合し、入力が止まって4秒で自動保存。企業には共有されない)
- 事前情報も入力が止まって4秒で自動保存。事前情報・実施記録の保存ログは同じ人・同じ面談で
  1時間に1行だけ残す(0138 `hm_log_access_once`)。閲覧・意見書・面談予定などのログは従来どおり毎回残す
- 意見書も入力が止まって4秒で自動保存(公開に切り替えた保存で実施済にする)。保存ログは同じ面談で1時間に1行
- ログイン不要の紹介用デモ(/demo): 架空企業「モデル株式会社」のデータで、健康診断管理・産業医面談(一覧・詳細・意見書の印刷様式)・
  個人カルテの画面を閲覧のみで表示(lib/demo-data.ts。データベースには触れない。ログイン画面からリンク)
- 企業担当者の健康診断管理は簡易表示: 有所見項目(C)・要医療項目(D)・就業制限項目(R)の列と、その絞り込み・集計行を
  出さない(就業判定・医師の意見・受診勧奨は表示)。実施者の画面は従来どおり。デモは「見る立場」で切り替え

- 「労基署報告（様式第6号）」ボタン: 転記用の数値(受診労働者数・所見のあった者・医師の指示人数・健診項目別・産業医)を
  1枚にまとめた印刷/PDF用の画面(office・company とも。デモにもあり)。健康診断管理の転記用集計は最初から開いて表示
- 健診機関の判定表記(「B1」「要観察」「要精密検査」など)は取込時に A〜E に読み替えて判定に入れ、元の表記は値として残す
  (lib/gradeText)。有所見・要医療の判定や個人票の表示も同じ読み替えを使うため、過去に「要観察」のまま取り込んだ記録も C として扱う
- 取込の自動割り当てで、B型・C型肝炎の抗原・抗体(HBs抗原・HBs抗体・HBc抗体・HCV抗体 など)、HIV・HTLV、
  「肝炎」「抗原」「抗体」「ウイルス」を含む見出し、尿沈渣(尿沈渣赤血球 など)・尿潜血、non-HDL コレステロール・LDL/HDL 比(L/H 比)などの「比」、肥満度の見出しは法定項目に割り当てず
  「取り込まない」を既定にする(Hb・HbA1c・赤血球数との混同防止)
- 自動判定の列でも、値が判定記号(B・C・E など)や指導区分の文言(要観察・要精密検査 など)なら、その記号を判定とする
  (「胸部X線指導区分」「心電図指導区分」のような列を自動判定のまま取り込んでも A にならない)
- 取込の日付(生年月日・健診日)は 2026/9/1・2026.9.1・20260901・2026年9月1日・和暦(S45.3.12、昭和45年3月12日、R7/9/1)・
  全角数字・Excelのシリアル値を読む。読み取れない値がある行は取込画面に件数と例を表示する
- 健診日の列は「健診日・健診年月日・受診日・受診年月日・受検日・検診日・健康診断日・実施日・実施年月日・検査日・診察日・測定日」などの
  見出しから自動で割り当てる(生年月日・判定日・作成日などは除く)。列が無い場合は取込画面の「全員共通の健診日」を全員に適用し、
  列の値が空欄・読み取れない行にも共通の健診日を使う。健診日の列が見つからず共通の健診日も未入力なら注意を表示する
